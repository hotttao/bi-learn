# S3：亲手理解一个可保存、可刷新的净收入看板

本文是操作教程。最终实测范围与证据以 README 的 S3 记录为准；脚本创建原生资产，不替代你亲手完成下面的练习。

## 1. 登录并辨认三个对象

用户指定使用本机局域网地址，访问 **http://192.168.2.46:8088**。用户名 `admin`，密码在本实验目录本地 `.env` 的 `SUPERSET_ADMIN_PASSWORD` 项中；密码未提交 Git。该地址是当前 DHCP 地址，地址变化时修改 `.env` 的 `SUPERSET_BIND_HOST` 并重建 Web 容器。

先找到名称以 `008` 开头的连接、数据集、图表和看板：

- 数据连接 `008 MySQL sales (read-only)`：指向容器网络内 MySQL，使用 `bi_reader`，数据库侧只授予 SELECT。
- 虚拟数据集 `008_order_net_v1`：保存 SQL、字段信息和指标定义，每行一订单。
- 图表 `008 净收入` 与 `008 按日净收入`：保存展示类型、指标和时间维度。
- 看板 `008 净收入入门看板`：保存图表引用、位置、大小和日期筛选范围。

虚拟数据集保存的是查询定义，不是订单数据副本；图表和看板也不是冻结的数据快照。源订单改变后，重新查询可以得到新结果。

## 2. 从订单和退款建立数据集

在 Superset 的 SQL Lab 中选择上述只读连接、`sales` schema，粘贴 [订单净收入 SQL](../sql/mysql/order_net.sql) 并执行。

先观察四行结果：订单 1～4 的净收入为 70、75、50、50。退款先按部门和订单汇总，再 LEFT JOIN 订单；无退款的订单保留，退款按 0 处理。订单日、部门和净收入是后续图表共用的字段。

你可以将查询另存为一个带个人后缀的练习数据集，避免覆盖脚本基线。打开数据集编辑，确认 `order_date` 是时间列，默认时间列为它；在 Metrics 中新增：

| 设置 | 值 |
| --- | --- |
| Metric name | `net_revenue` |
| SQL expression | `SUM(net_amount)` |
| Label | 净收入 |
| D3 format | `,.2f` |

为什么先定义指标？因为指标卡和趋势必须共用同一个口径。如果每张图分别拼一份“收入公式”，以后变更时容易出现不一致。

## 3. 创建净收入指标卡

从练习数据集创建图表，选择 Big Number（总值，无趋势线）类型。Metric 选择 `net_revenue`，时间列选择 `order_date`，范围固定为 `2026-10-01 : 2026-11-01`。

执行查询应得到 **245.00**。标题说明“净收入”，单位为人民币元，退款归属原订单日。保存图表，并加入自己的练习看板。

## 4. 创建按日趋势

仍使用同一个数据集，选择 ECharts 时间序列折线图。X 轴为 `order_date`，时间粒度 Day，Metric 为 `net_revenue`，时间范围与指标卡一致。

应看到 10 月 1 日 **120**、10 月 2 日 **125**，两天合计 245。将图表保存到同一练习看板。这里没有客户行业：跨源行业关联属于 S4，不在本步偷偷从 CRM 复制一张表代替。

## 5. 日期筛选与布局

编辑看板，添加 Time range 类型的原生筛选器，名称“订单日期”，作用范围包含两张图，默认范围为 2026 年 10 月。保存后，将范围改为 `2026-10-01 : 2026-10-02` 并应用，指标卡应为 **120**，趋势仅保留第一天。再恢复完整月份，应回到 **245**。

日期范围采用左闭右开。这里只筛选订单日；即使退款发生在 10 月 3 日，仍影响对应订单日的净收入。

进入 Edit dashboard，拖动图表位置并调整大小，保存，离开页面后重新打开。检查布局是否保留；编辑布局不会改变数据集 SQL 或收入公式。

## 6. 源更新与刷新

这项练习由具备实验管理员权限的人执行，BI 只读账号不能修改订单。将订单 2 实付从 80 改为 90 后，重新查询/刷新看板，应得到 **255**；趋势第二天应为 **135**。随后将订单 2 恢复为 80，再刷新回到 **245** 和第二天 **125**。

对应管理员 SQL：

```sql
UPDATE orders SET paid_amount=90.00 WHERE order_id=2 AND dept_id='A';
-- 观察完毕必须恢复：
UPDATE orders SET paid_amount=80.00 WHERE order_id=2 AND dept_id='A';
```

可以用 `sudo python3 scripts/source_db.py query --source mysql --role admin` 从标准输入执行单条 SQL。修改源数据前记录原值，异常退出后检查并恢复；不要期待 seed 自动覆盖手工修改。

本实验关闭了查询结果缓存，避免首次学习时将缓存误判为 SQL 错误。刷新显示当前数据，保存看板保留的是配置。用户、看板和数据集配置保存在独立 PostgreSQL 元数据库，和订单/退款的业务卷不同。

## 7. 本步与下一步的边界

本步完成后应能解释：数据集、指标、图表和看板分别保存什么；退款为什么要先聚合；日期筛选作用于哪个字段；刷新与保存为什么是两件事。

跨库查询、部门隔离、Superset MCP 和 Wren 都在后续步骤。当前管理员可读全量合成数据，不作为部门隔离验收身份。
