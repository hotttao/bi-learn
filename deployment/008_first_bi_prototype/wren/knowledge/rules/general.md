# 008 销售语义规则 v1

## 指标和时间

净收入 net_revenue@1（受控别名“净销售额”）=实付减已记录退款。单位人民币元，展示两位小数。它不是财务收入确认；仅问“收入”时澄清。优先使用 net_revenue cube 的 total；也可 SUM(bi_orders.net_amount)。默认回归窗口为 [2026-10-01, 2026-11-01)，不是随时钟变化的“本月”。业务日期 Asia/Shanghai，退款回溯原订单日。

## 关系与粒度

bi_orders 每行一订单，order_id 全局唯一。bi_refund_totals 是原始退款按 (dept_id, order_id) 汇总的结果，再与 bi_orders 关联；不关联退款明细后重复求和实付。bi_customers 主键为 (dept_id, customer_id)，关联必须保留两个字段。缺失客户时保留订单，行业为“未知行业”。原始退款明细不是本项目的查询模型。

## 行业、质量与权限

行业为客户当前行业，更新后历史订单重新分组；无法回答下单时行业。重复客户键、累计退款超过实付等需要外部质量检查拒绝发布，MDL 的基数声明不能代替实际数据质量校验。

strict_mode 只约束本入口的模型引用和只读语句；本实验没有部门认证/隔离。部署会话能访问 Trino 原始源，不代表普通用户已受保护。不要将本地未认证入口当作团队服务。

## 变更和 BI

模型源 YAML → validate → build → 回归。当前使用 grep 知识后端，memory index 是无索引可构建的 no-op；尚未测试向量检索。MCP 和 Codex 工具接入在 W2，语义变更发布在 W3。Superset 仍使用 S4 SQL，不会因 Wren YAML 改动自动更新。知识 Markdown 是 Agent 上下文，不是引擎强制规则。

## 已知兼容限制

当前引擎对同名物理表的限定名存在模型范围绕过，模型统一用 bi_ 前缀避开已连接物理表名；仍不得将 strict_mode 宣称为完整授权边界。当前项目没有与 bi_ 模型同名的物理表；新增源表时需重新检查名称冲突与范围测试。关联目标键使用不同别名，避免引擎在外关联时从无匹配一侧投影同名键。

## 金额兼容约定

当前版本在 MDL 列类型使用通用 DECIMAL，源字段精度另存 properties.source_type；这份属性不是引擎精度保证。SQL 中的非整数金额常量使用显式 CAST('0.01' AS DECIMAL(12,2))，不要使用会被本版本翻译丢失标度的 DECIMAL '0.01'。回归必须包含“分”级值并使用 Decimal 对账，不能只看整数 245。
